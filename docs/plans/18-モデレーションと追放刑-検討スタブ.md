# 計画18: 記憶を持つモデレーターと追放刑（検討スタブ）

## 実装状況: 未着手（検討スタブ——本計画は意図的に粗い）

**オーナー決定（2026-07-03）: モデレーション周りは一旦後回し。** AIモデレーターの実行基盤となるコンピューティングリソースが現時点で存在しないため、本計画は「検討・開発が必要」という事実の記録と、着手判断の材料の整理に留める。

## 目的（構想の対応箇所）

- 技術6「記憶を持つモデレーター」: 永続記憶を持つAIがモデレーションを担い、人間かAIかは参加者に分からない
- 追放刑: 発言権と蓄積実績の喪失、非ログイン相当の閲覧への降格
- ルール1違反（公開の詮索）のモデレーション

## 分かっていること（knowhow 調査済み・再調査不要）

`docs/knowhow/moderation-mechanics.md` に詳細あり。要点:

- **Misskey 側の受け皿は既存機構でほぼ足りる**: bot アカウント + moderator ロール + スコープ絞りアクセストークン + admin stream（WebSocket）購読で、通報のリアルタイム受信から処罰・解決まで API で完結できる
- **suspend はフォロー関係を不可逆破壊する**——誤検知からの復帰と相性が悪い。追放刑は可逆な exile フラグの新設を検討する価値がある（設計材料は knowhow 参照）
- **閲覧降格の接続点は計画11が用意済み**: 計画11の `isRestrictedViewer(user)` 述語に `isExiled` を足すだけで、REST・ストリーミングの両方に「非ログイン相当への降格」が一貫適用できる。本計画の昇格時は計画11の該当設計を参照すること
- AIモデレーターは `isAdministrator` にしない（human が AI を通報できなくなる）。`isModerator` に留める
- 「記憶」の部分（過去パターン参照・文脈の一貫性判断）は Misskey 側ではなく**エージェントハーネス側の責務**——ここが未解決の本体

## 未解決の問い（着手時に決めること）

1. **実行基盤**: AIモデレーターエージェントをどこで常駐させるか（現状リソースなし。これが後回しの理由）
2. **記憶基盤**: 永続記憶（memory MCP 等）の構成。モデレーターこそ Memory Gate を通る存在である必要がある
3. **判断の透明性**: moderationLog の info jsonb に判断根拠・確信度を残す設計（機構はある。何を残すかが未定）
4. **人間フォールバック**: AIモデレーター不在の間は運用者の手動モデレーション。規約（計画12）の詮索禁止も当面は手動運用
